# 示例 · Amazon OA → VO 上岸

<div class="case-figph">📌 <b>本页是「案例模板」示例</b>，用于展示案例的组织方式与图文排版；正式内容将替换为<b>真实、匿名、经学生同意</b>的案例（含真实截图）。<b>不承诺保 offer</b>，结果受个人投入、市场与运气影响。</div>

## 学生背景（匿名）
- **目标**：Amazon SDE 实习 · OA + VO 环节
- **起点**：刷了不少题但"看题解会、自己写不出"；OA 常因边界 / 复杂度挂，VO 一紧张思路就断
- **时间线**：面试前约 4 周

## 痛点诊断
- 没有**可迁移的解题框架**——遇到新题不会做"信号识别 → 选解法"
- 高频题型（滑动窗口 / 单调栈 / 图 / DP）缺系统梳理
- VO 缺乏**边讲边写**的表达训练，沟通与 edge case 意识弱

## 辅导方案（一步步怎么带）
1. **建框架**：按"题目 → 约束 → 信号识别 → 最优思路 → 复杂度 → AC 代码"统一拆解，训练"看到什么特征想到什么解法"。
   <div class="case-figph">🖼️ 配图位：高频题型 → 解法 的信号识别对照表 / 思维导图。</div>
2. **打高频**：按公司高频题型做专题，先讲规律再练透。
3. **VO 陪练**：全真模拟 —— 边讲思路边写，训练澄清需求、边界讨论、复杂度分析与测试。
   <div class="case-figph">🖼️ 配图位：一道真题的"信号识别 → 思路 → AC 代码"讲解截图。</div>
4. **限时辅助 + 复盘**：限时环境找暴露的坏习惯，逐一纠正。

## 关键考点抓手
- 滑动窗口 / 单调栈 / 差分 / 图论 / DP 的**触发信号**与模板
- 复杂度分析 + edge case 清单
- VO 沟通话术：澄清 → 举例 → 思路 → 编码 → 测试

## 结果（示例）
- <span class="case-badge">通过 OA + VO，拿到 Offer（示例）</span>；更关键的是"拿到新题也有稳定框架去拆"。
- 学生反馈（匿名，示例）：「不再靠背题，是真的会做题了。」
